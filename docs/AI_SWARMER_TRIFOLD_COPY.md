## INSIDE FLAP — THE NEW ATTACK SURFACE
### Your next employee may be software.
Enterprises are connecting AI agents to email, files, CRMs, code, cloud infrastructure, browsers, APIs and financial workflows. Those agents can inherit permissions and take actions at machine speed.

Traditional endpoint and network security remain essential. Agentic systems introduce two additional questions:

**Should this capability be allowed to act at all?**

**If trusted work is interrupted, can it safely resume from a known-good state?**

SWARMER is designed to answer both questions before trust becomes access or recovery becomes another attack path.

## INSIDE CENTER — CONTINUOUS TRUST + KAMERON RECOVERY
### Trust expires when software changes. Recovery must be trusted too.
SWARMER creates a cryptographic capability passport for approved software: source, publisher, version, permissions, dependency state, fingerprint and approval history.

Change the code? Revalidate.
Change a dependency? Revalidate.
Expand permissions? Revalidate.
Change publisher or fingerprint? Revalidate.

The embedded **KAMERON Resilience Engine** adds checkpoint-aware continuity for protected jobs and agents. KAMERON captures recoverable execution state in a **Trusted Recovery Capsule**. Before SWARMER permits a resume, it can verify capsule integrity, Capability Gate approval, behavioral verification, environment identity, policy version and trust score.

**CHECKPOINT EXISTS ≠ SAFE TO RESUME**

SWARMER + KAMERON follows: **checkpoint → verify → approve → resume → monitor → re-checkpoint.**

## BACK LEFT — BUILT FOR THE AI ERA
### Conventional security protects infrastructure. SWARMER adds governance for autonomous capability and safe continuity.
The cybersecurity market is moving toward zero trust, AI workload protection, AI supply-chain security, agent inventories and runtime controls. SWARMER concentrates on admission, continuing trust and auditable autonomous behavior while KAMERON supplies the resilience bridge for approved workloads.

KAMERON is also designed as a standalone product and integration layer. Inside SWARMER, it serves as the embedded resilience module. Recovering arbitrary external software requires a KAMERON Runtime, SDK, worker agent or integration adapter running where that software executes; the SWARMER control plane alone does not magically reconstruct outside applications.

It is not 'install it once and trust it forever.'
It is **verify → isolate → observe → approve → fingerprint → monitor → checkpoint → verify recovery → resume → revalidate.**
