# RUN116 — SWR-TXT-007 — Name the Abuse Case Before the Control Test

## Customer Truth
A control receipt without a declared adversarial or abuse case can become ceremonial. An enterprise buyer should name what the bounded test will attempt to resist, deny, contain, or force through revalidation before contact.

## Creative Strategy
**Hook:** Name the abuse case before the control test.

**CTA:** Choose one bounded workflow, one adversarial/abuse case, the authority boundary, enforcement path, trust-expiry rule, and the receipt that would make the test worth reviewing.

Supported planning categories in RUN116: prompt injection, permission escalation, secret exfiltration, tool/capability abuse, supply-chain or capability change, unauthorized data egress, or another buyer-defined case.

## Claims Boundary
Selecting an abuse case does not establish that SWARMER can currently block it in a production environment. Protection claims require a connected enforcement path, executed test, preserved evidence, and independently reviewable result.

## Market evidence
NIST's 2026 work on software and AI-agent identity and authorization highlights risks created when agents gain access to data, tools, and applications, including the need for authorization, auditability, and security controls. This supports explicit abuse-case testing; it is not SWARMER certification or performance evidence.
