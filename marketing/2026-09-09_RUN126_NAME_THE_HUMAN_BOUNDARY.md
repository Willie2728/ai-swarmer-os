# SWR-TXT-009 — Name the Human Boundary Before the Control Test

## Customer Truth
An empty human-approval field is ambiguous. It can mean “no consequential action exists,” or it can mean the buyer never defined who keeps authority. A security control test should not treat those states as equivalent.

## Hook
**Name the human boundary before the control test.**

## Deployable copy
Before an enterprise SWARMER scope becomes ready, define one abuse case, the authority surface, the consequential actions that remain under explicit human approval — or explicitly state that none exist in this bounded workflow — the trust-expiry trigger, enforcement path, failure mode, and the control receipt required for review.

## CTA
Define the human approval boundary, then copy the one-workflow control-test brief for internal security review before sharing contact.

## Claims boundary
This is buyer-supplied scoping context. It does not prove a runtime approval gate exists, that an enforcement adapter is connected, that an abuse case has been blocked, that a pilot was accepted, or that SWARMER provides complete protection.
