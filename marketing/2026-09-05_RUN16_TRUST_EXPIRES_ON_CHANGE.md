# AI SWARMER OS — Growth Run 16

## Campaign
**Trust Expires on Change**

## Buyer
CISO, CTO, AI platform lead, enterprise architect, security engineering leader.

## Hook
**The most dangerous capability may be the one you approved yesterday—before it changed.**

## Product-grounded story
AI SWARMER OS separates source identity from payload trust. A capability can be approved, fingerprinted, and admitted, then forced back through revalidation when its code, dependency state, permissions, publisher, version, behavior, or fingerprint materially changes. Claimed-vs-observed mismatch can trigger quarantine rather than silent trust carryover.

## 30-second creative structure
1. APPROVED badge appears on an agent skill.
2. Dependency/fingerprint changes.
3. Badge expires: REVALIDATION REQUIRED.
4. Red Room compares claimed behavior with observed behavior.
5. Capability either receives a renewed passport or is quarantined.
6. End card: **Trust is not permanent. It is continuously earned.**

## CTA
Run the capability through the gate.

## Claims boundary
This is an operational MVP and not a claim of complete network protection or independently validated superiority. Production enterprise deployment still requires the enforcement adapters, authentication, secrets, tenant isolation, sandboxing, scanning, backups, and independent security validation described in the repository README.
