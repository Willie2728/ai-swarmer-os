# WCL Five-Minute Film — "When AI Can Act"

## Production standard
Serious broadcast-documentary tone. Photoreal studio. Professional male presenter, approximately 38–45, glasses, tailored charcoal suit, white shirt, understated tie. Calm, authoritative delivery. No sensational disaster imagery. Use WCL and product logos as supplied/approved. Graphics should feel like a premium technology documentary: clean dark studio, large LED wall, restrained motion graphics, real product UI captures wherever available. Do not imitate any specific news network branding.

## 0:00–0:35 — OPEN: THE TRANSITION
VISUAL: Black screen. Sparse pulse. Rapid, elegant montage: AI assistant answering a question; coding agent opening a terminal; agent calling an API; automated browser submitting a form; enterprise network map lighting up.

PRESENTER: "Artificial intelligence is crossing an important line. It is moving from systems that answer questions to systems that can act — systems that can use tools, write code, call APIs, move data, communicate with other software and make changes in the real world. That capability can create extraordinary value. It also creates a new control problem."

ON SCREEN: ADVICE -> AUTHORITY

## 0:35–1:05 — WHY NOW
VISUAL: Editorial-style headline wall referencing the current public debate without reproducing copyrighted broadcast clips. Text cards: FRONTIER AI SAFETY; AGENT CONTAINMENT; BLAST RADIUS; SECURE AUTONOMY. Small source line: public statements and research from frontier AI labs and standards bodies.

PRESENTER: "In 2026, that control problem moved into public view. Frontier AI leaders have warned that increasingly capable agents require stronger safeguards. Anthropic has publicly described the need to cap an agent's blast radius through containment. NIST has said that AI agents introduce novel security threats requiring cybersecurity practices to adapt. The question for every organization adopting autonomous AI is becoming clear: how do we gain the productivity without surrendering control?"

ON SCREEN: AUTHORITY | DETECTION & CONTAINMENT | TRUSTED RECOVERY

## 1:30–2:15 — SOVRAIL
VISUAL: Agent request approaches an API boundary. Scope, budget and intended effect appear as a digital envelope. Unauthorized route turns red.

PRESENTER: "SOVRAIL is the execution boundary. It gives agents and applications scoped credentials instead of unrestricted provider secrets. It can enforce request ceilings and spending limits, route across approved providers, reduce duplicate work and record the intent, context and observed effect of an action. If an external system changes without a matching authorized effect, that is not simply another log entry. It becomes a security decision."

ON SCREEN: INTENT -> AUTHORITY -> EXECUTION -> EFFECT -> VERIFICATION

## 2:15–3:20 — AI SWARMER OS
VISUAL: Capability arrives: MCP tool / skill / repository / connector. Guest List verifies source. Capability Gate fingerprints it. Runtime telemetry streams. One action attempts credential access and novel egress. Screen shows REVIEW, then BLOCK / CONTAIN.

PRESENTER: "AI SWARMER OS is the trust and runtime security control plane. It is designed to ask two different questions: who or what is requesting access — and should the capability itself be trusted? SWARMER evaluates defined risk signals including unapproved tools and destinations, credential access, prompt-injection indicators, unusual outbound transfers, unexpected external writes, excessive delegation and signs of possible covert multi-agent coordination. Capabilities can be fingerprinted, and material change can trigger revalidation."

VISUAL: Approved capability v1.7 becomes v1.8. Fingerprint changes. TRUST EXPIRED — REVALIDATION REQUIRED.

PRESENTER: "Trust is not treated as permanent. Software changes. Dependencies change. Permissions change. Behavior changes. SWARMER is being developed so authorization can change with them."

ON SCREEN: ZERO TRUST FOR AUTONOMOUS ACTION.

## 3:20–4:05 — KAMERON
VISUAL: A workflow is contained. A timeline rewinds to a signed checkpoint. State capsule shows environment fingerprint, permissions snapshot and trust state.

PRESENTER: "When an autonomous workflow must be interrupted, KAMERON AI OS becomes the resilience layer. KAMERON creates integrity-protected recovery capsules containing the state needed to resume work. But its governing principle is deliberately stricter than ordinary backup: a checkpoint existing does not mean it is safe to resume. Recovery can require renewed trust, environment validation and SWARMER clearance before execution continues."

ON SCREEN: CONTAIN -> PRESERVE -> VERIFY -> RECOVER

## 4:05–4:35 — THE STACK WORKING TOGETHER
VISUAL: Full animated architecture.

PRESENTER: "Together, the architecture is straightforward. SOVRAIL defines and controls the execution boundary. SWARMER evaluates trust, behavior and policy. KAMERON preserves recoverability when work must stop. The objective is not to slow useful AI down. It is to create the control infrastructure that allows organizations to use increasingly capable autonomous systems with clearer boundaries, evidence and recovery paths."
